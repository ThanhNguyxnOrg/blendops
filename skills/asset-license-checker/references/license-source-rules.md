# License-source rules

A license is valid evidence only if it can be sourced. Vague "I think this is CC0" is Warn at best.

## Acceptable license sources

1. License field in the asset's metadata file (preferred).
2. Public license page on the source platform (URL recorded).
3. License text bundled with the asset (LICENSE.txt or similar).
4. Direct correspondence with the licensor (email proof).

## Unacceptable

- "I remember it was CC0."
- A second-hand description from another site.
- A blog post that describes the asset.
- Verbal confirmation without a written record.

## Recording

For each asset, capture:
- License name (canonical, e.g., "CC0 1.0", not just "CC")
- Source URL of the license page
- Date checked
- Asset version / file hash if available

This becomes part of the per-asset row in the verdict table.

## License changes over time

Licenses can change retroactively for new versions but typically not for previously-downloaded files. Record the version number / download date as evidence of which license applies.

## Bundled assets with mixed licenses

Asset packs often bundle assets under multiple licenses. Treat each sub-asset separately; do not apply the most-restrictive license uniformly (it may over-block).
